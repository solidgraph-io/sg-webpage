# Prompt 43 — OKF Fase 2: índices por carpeta + aplicación permanente

> Pégale esto a Claude Code en la raíz del repo `sg-webpage`. Implementa RF-7/RF-8 de SPEC-DOCS-OKF-001
> (Fase 2 de ADR-0015, con el gate CI adelantado). TDD + trazabilidad. Contra `develop`.
> Rama `feat/okf-phase2-indexes` **desde `develop`**; al terminar y verde: **merge y borra la rama**.

---

Eres un implementador en `sg-webpage`. Lee `AGENTS.md` §4, **ADR-0015** y **SPEC-DOCS-OKF-001**
(RF-7 gate CI, RF-8 índice por carpeta).

## Objetivo

Completar el bundle OKF con **progressive disclosure** (un `index.md` por subdirectorio) y hacer que la
conformidad se **aplique siempre** (okf:check en CI + gobernanza en `AGENTS.md`).

## 0. Pre-requisito — hacer visible `SPEC-DOCS-OKF-001` al gate de trazabilidad

Hay un bug en el gate: `parseSpec` (`scripts/trace.ts:50`, regex `SPEC-[A-Z]+-\d+`) y el regex de citas
(`trace.ts:94`) solo aceptan dominios de **un** segmento, así que `SPEC-DOCS-OKF-001` (dominio compuesto
`DOCS-OKF`) es **invisible**: no entra en la matriz y sus citas `[SPEC-DOCS-OKF-001/RF-x]` no se cuentan. Por
eso el `trace --check` verde de la Fase 1 **no** cubría esta spec — y sin este fix, los tests de RF-8 que
añades abajo **tampoco** gatearían. Arréglalo en dos capas:

1. **Generaliza el regex** en ambos sitios a `SPEC-[A-Z]+(?:-[A-Z]+)*-\d+` (soporta dominios compuestos).
   **No renombres** la spec: el ID es estable (SPEC-TEMPLATE).
2. **Cierra la clase de bug (lo importante):** haz que `pnpm trace -- --check` **falle** (no ignore en
   silencio) si existe un `docs/specs/SPEC-*.md` que **no parsea** a un ID válido o que **no aporta ninguna
   RF reconocida**. Un spec invisible al gate es el peligro real; ningún spec debe volver a escaparse.
3. **Tests de trace** `[SPEC-…]`: parseo de dominio compuesto (`SPEC-DOCS-OKF-001` → ok) y que un
   `SPEC-*.md` no parseable/ sin RFs **rompe** `trace --check`.

Tras esto, confirma que **RF-1..RF-8 de SPEC-DOCS-OKF-001 quedan cubiertas y contadas** por el gate (las RF-1..6
ya tienen tests desde la Fase 1; RF-7/RF-8 llegan en este prompt).

## 1. Generador de índices — `pnpm okf:index` (TDD)

Crea un generador (Node/TS, misma línea que el checker/`trace`) expuesto como **`pnpm okf:index`** que, per
**OKF §6**, genera/actualiza un `index.md` en cada **subdirectorio no vacío** de `docs/`
(`specs/`, `adr/`, `prompts/`, `deploy/`) y refresca el **índice raíz** para enlazar a esos sub-índices.

- Formato §6: **sin frontmatter** en los índices (el único con frontmatter es el raíz, solo `okf_version`).
  Body = secciones con bullets `* [Title](archivo.md) - description`, tomando `title`/`description` del
  frontmatter de cada concepto. Ordena estable (p. ej. por nombre de archivo) para diffs limpios.
- **Idempotente**: correrlo dos veces no produce diff. Marca los archivos como generados (comentario
  `<!-- generated by okf:index -->`) para no editarlos a mano.
- Tests `[SPEC-DOCS-OKF-001/RF-8]`: cada subdir tiene index tras generar; idempotencia (segunda corrida sin
  cambios); el índice raíz enlaza a los sub-índices; los índices no llevan frontmatter.

## 2. Checker — añadir RF-8 (warning)

Extiende `scripts/okf-check.ts` (+ tests) para que **RF-8** avise (warning, exit 0) si un subdirectorio no
vacío carece de `index.md`. Tras generar en el paso 1, ese warning debe quedar en **0**.

## 3. Gate CI — RF-7 (que se use siempre)

Cablea **`pnpm okf:check`** como step de CI **junto a `pnpm trace`** (su propio step, no bloquea el build de
la app pero sí el pipeline si hay violaciones duras).

- Esto toca `.drone.yml`. **Ojo**: si `deploy-001.test.ts` (o `SPEC-DEPLOY-001/002`) asevera la lista de
  steps del pipeline, **actualiza ese test + la spec** citándolos (`[SPEC-DEPLOY-…/RF-y]`), para no romper la
  coherencia test↔spec (lección de ADRs previos).
- Añade `pnpm okf:index -- --check` (modo verificación, falla si el índice está desactualizado) al mismo step
  o a `trace`, para que un índice obsoleto no llegue a `develop`.

## 4. Gobernanza — OKF por defecto de ahora en adelante

- **`AGENTS.md`**: añade una cláusula breve (donde estén las reglas de docs/flujo): *"Todo `.md` nuevo bajo
  `docs/` nace con frontmatter OKF (`type` según la taxonomía de SPEC-DOCS-OKF-001) y su carpeta mantiene su
  `index.md` (`pnpm okf:index`). `pnpm okf:check` debe estar verde antes de abrir PR."*
- **Scaffold de specs**: si el comando `/new-spec` (`.claude/commands/`) copia `SPEC-TEMPLATE.md`, haz que
  **emita el frontmatter** (`type: Spec` + `title`/`description`/`timestamp`) para que las specs nuevas nazcan
  conformes. Si no hay scaffold, añade al **cuerpo** de `SPEC-TEMPLATE.md` un bloque copy-paste con el
  frontmatter OKF a usar (el `type` del template en sí sigue siendo `Reference`).

## Verificación antes de "listo"

```
pnpm okf:index && git diff --exit-code docs/**/index.md   # idempotente: sin cambios en 2ª corrida
pnpm okf:check                                            # 0 errores, 0 warnings (RF-8 satisfecho)
pnpm lint && pnpm type-check && pnpm test && pnpm trace -- --check
pnpm exec prettier --write .   # sin romper frontmatter ni los index generados
```

- Índices por carpeta presentes y enlazados desde el raíz; okf:check y su suite verdes; CI con el step nuevo;
  `deploy-001` y su spec coherentes si se tocaron.

## Entregable

`index.md` en `specs/`, `adr/`, `prompts/`, `deploy/` (progressive disclosure §6) + raíz enlazando; `okf:check`
con RF-8; `pnpm okf:check`/`okf:index --check` gateados en CI (RF-7); `AGENTS.md` + scaffold garantizan que
OKF se use siempre. Reporta archivos tocados y cualquier test/spec de deploy ajustado.
